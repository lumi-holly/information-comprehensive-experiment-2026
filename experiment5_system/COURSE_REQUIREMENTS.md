# 实验五课件要求与本工程的对应关系

本说明依据本地课程目录中的课件核对；课件原件没有上传到本代码仓库。课件的要求、以前实验代码采用的参数，以及本工程建议值分别列出，不能互相替代。

## 1. 需要串联的完整系统

实验五课件《8.+专业综合实验（实验五）》第 2 页总体框架图包含语音采集、时域与频域分析、信号加噪与模拟加密、信源编码与数字加密、信道编解码、信源解码与数字解密、信号滤波、嵌入式平台实现、质量评价。

本工程的处理顺序为：

```text
发送端：WAV/麦克风 → 保存参考语音并分析 → 加入正弦干扰
       → DPCM8/PCM16 → AES-128-CBC + HMAC → Hamming(7,4)/不加信道码
       → TCP 真实网络
接收端：收到数据 → 信道译码 → 认证并解密 → 信源解码
       → 连续 FIR 带通滤波 → 保存/可选播放 → 分析与质量评价
```

正弦叠加用于延续实验一的加噪处理，也可观察模拟扰码后再滤波的效果；它并不提供密码学安全。数字数据的机密性由 AES 提供，认证由 HMAC 提供。本工程没有用“加噪声”代替数字加密。

## 2. 阈值和参数的来源

| 参数或范围 | 来源 | 本工程如何使用 |
| --- | --- | --- |
| `fs > 2*fmax` | 实验一第 11 页采样定理 | 干扰频率与滤波上截止频率必须小于 `fs/2`，不满足时拒绝运行 |
| 实际采样率一般为最高频率的 2.56～4 倍 | 实验一第 11 页的实际使用指导 | 用于选择采样率，不视为任何输入都必须达到的程序合格分数 |
| 话音通常 300～3000 Hz，发音器官 80～3400 Hz | 实验一第 7 页背景知识 | 作为语音带通设计参考，不写成老师指定的硬性截止频率 |
| 16 kHz、16 bit、单声道、5 秒 | 既有实验一 MATLAB 代码 | 沿用作麦克风采集的默认配置，WAV 模式读取文件实际采样率 |
| 5000 Hz 正弦干扰、幅值 0.2，带通 300～3400 Hz | 既有实验一 MATLAB 代码 | 延续加噪与带通频段，保证叠加前有足够幅值余量 |
| 8 bit DPCM、量化步长 `2/127` | 既有实验三代码 | 默认信源编码基准，逐帧独立预测，使用 MATLAB 风格取整 |
| Hamming(7,4) | 实验三第 29 页及既有代码 | 默认信道编码，也可关闭作为对照；关闭后不能声称仍有汉明纠错 |
| 129 tap FIR、源信号幅值乘 0.75、网络帧长/超时/资源上限 | 本工程实施建议 | 为连续处理、避免加噪削波、控制资源开销设置；不是课件阈值 |
| 模拟随机 BER、固定随机种子 | 联调和可重复对照的实验配置 | 仅用于程序主动翻转比特，不作为真实 TCP 网络测得的误码率 |

默认 16 kHz 的奈奎斯特频率为 8 kHz，因此 5 kHz 干扰和 3.4 kHz 滤波上限均在可表示范围。若把最高成分计为加入的 5 kHz 干扰，`16000/5000=3.2`，也处于课件给出的 2.56～4 倍一般指导范围。

课件没有给固定的时延上限、BER 上限、SNR 合格线、帧长或自动切换阈值。本工程的参数合法性检查和资源保护上限不代表老师的考核阈值。未经测量，不预写“达到实时”“音质提高”“开发板更快”等结论。

## 3. 与既有 MATLAB 实验保持一致和需要说明的差异

- 保留原始 WAV 作为共同输入。比较时确保采样率、语音时长、幅值缩放、编码方式、误码条件一致。
- DPCM8 采用相同量化步长和取整规则。网络版逐帧重置预测器；实验三整段预测与分帧预测在边界处不同，不能直接要求两者整段逐样本一致。
- AES 保留教学使用的 CBC 模式，改用随机 IV 并加入 HMAC。每次密文可以不同，应该验证认证成功和明文一致，不比较两次密文是否相等。
- 汉明码的非零校验子次数表示执行了位翻转的码字数。仅凭该次数，不能断言多比特错误都成功纠正。最终认证通过后，才接受恢复数据。
- 旧 MATLAB 实验一使用 6 阶 Butterworth 与离线 `filtfilt`。本工程自编 129 tap 因果 FIR，跨帧保留状态，默认固定群延迟 64 个样本，即 16 kHz 下 4 ms。质量评价可补偿此延迟，但滤波器响应和边界仍与旧算法不同。
- FIR 的 4 ms 是滤波器自身群延迟，不是完整系统的端到端延迟。音频缓冲、分帧、编码、网络与播放都可能增加等待。
- 程序记录的请求往返时间包含接收端处理和确认，不等于纯网络传播时延。未同步的两台设备不能直接相减时钟得到单程时延。
- 时域 CSV 可为显示抽取点；频谱最多分析前 32768 个样本。文件中会标注样本范围，不能把前缀频谱说成整段 FFT。

## 4. 老师提示的多方案与优化如何落地

本工程先手动选择模式，使每种方案能独立复现。PCM16/DPCM8 体现信源编码的音质与数据量取舍；Hamming74/不编码体现纠错保护与冗余取舍。比特打包减少传输表示的浪费，NumPy 批量汉明译码减少 Python 循环开销。

采集部分通过后台线程和默认 16 帧有界队列与网络发送解耦。队列容量属于实施建议；满队列、输入溢出均明确停止本次运行，不通过丢样本维持“成功”。这项实现仍需实物音频设备验证，不能凭线程结构声称已满足实时性能。

课件实验三第 24、26 页还介绍 Lloyds 优化量化和 `dpcmopt`。这些是可进一步研究的策略，本工程没有实现它们，也没有把当前实现描述为完成上述优化。ADPCM/APCM 同样属于候选方法，不应列为已实现功能。

是否选择某个模式，最终依据同一输入下实测的有效字节数、音质指标和处理耗时。自动切换阈值只有在取得数据并经老师要求确认后再定义。

## 5. 验收证据边界

软件自动测试只验证算法、异常处理和协议实现。本机测试不作为真实网络实验结果。正式验收应在 Windows 与实际 RK3399 Ubuntu 之间通过网线或 Wi-Fi 运行，检查完整结束标记、认证结果、输出 WAV、处理统计与质量指标。

麦克风采集、扬声器播放、板端依赖安装与处理速度，必须在对应硬件上运行后才能写为“实测”。如果尚未运行，在报告中明确标注“未测”。
